# 本机升级实验台

维护者安装 Node 22、项目锁定的 pnpm、Git 和 mongod，完成 `pnpm install`。在干净、受信任的项目分支运行 `pnpm upgrade:lab`，打开 <http://127.0.0.1:18794/>。常规员工端也可输入 `/升级 文件结果支持 XLSX` 跳转，不会将需求发给企业知识库。

1. 在本机员工对话发送 `/升级 新增工时汇总工具，每行输入类别和分钟数，按类别合计。`。18790、5180 的员工端直接创建任务；候选页面只提供跳转。所有新需求交给模型，旧配方仅用于恢复历史任务。已有 XLSX 不必再次升级。
2. 每单基于提交哈希新建 `codex/upgrade-*` 分支和工作树，修改、提交、类型检查、构建并运行单元测试。XLSX 还必须通过实际 HTTP 生成、工作簿预览、下载及跨用户隔离检查。失败不触碰当前分支。
3. 在记录里查看差异和独立预览。预览使用自己的 MongoDB 进程、数据目录与随机本机端口，没有复制环境文件或模型密钥。只填测试数据。停止实验台会停止它启动的预览；再次启动后，可在记录中恢复。分支、记录、工作树和数据库保留在本地。
4. 满意后，手动执行记录里包含**完整提交哈希**的 `pnpm upgrade:accept <编号> <哈希>`。它要求基线分支、原始提交、干净工作树与候选提交一致，只允许快进合并；不部署、不推送、不替换桌面安装包。

模型使用本机配置的 OpenAI 服务端密钥（环境 `OPENAI_API_KEY` 或已有配置 `backend/.env.openai.local`），可用 `UPGRADE_MODEL` 指定支持 JSON 输出与 Chat Completions 的模型。会产生模型费用。只发需求、相关已有工具及合成样例，不发整库、企业数据或配置；不要在需求里粘贴敏感信息。失败不会冒充成功或回退到模板。

模型先设计输入、按钮和至少两个精确输出的验收样例，再为员工端工具编写真正的 JavaScript；测试不通过最多生成三版，冻结的预期保持不变。验收用例和源码保存在 `web-app/src/features/generated/` 中，可在 diff 中分别审阅。需求提到完整工具名时会尝试在原工具上修改，旧样例仍要通过。打开候选的「工作台工具」实际试用；模型生成的测试不等于独立的业务验收。

边界：支持多输入、多按钮、纯文本输出的离线工具，不开放鉴权、数据库、shell、网络或任意仓库修改。源码文本只在 QuickJS/WASM 中运行，不交给 Node 或浏览器原生 eval，没有宿主绑定；浏览器 Worker 有内存、栈和时间限制。宿主只用文本节点渲染输出。开发服务只供本机使用；不要代理到公网或在不可信基线上运行。

建议在需求末尾单独加一行 `验收：{"输入":["研发,0"],"输出":"研发：0"}`。输入按字段排列，多按钮时可加 `"操作":2` 指定第几个按钮。模型先复核验收草案，再由程序锁定这些预期；冲突、运行不符或页面回归失败均不能合并。测试数据须使用合成样例。

预览公布前还会在候选地址上运行 Playwright 浏览器回归，需要先安装项目使用的 Chromium（`pnpm exec playwright install chromium`）。
