# 路线图：欢迎一起提想法

当前版本是用于验证企业 AI 工作伙伴的早期可运行原型，路线图是讨论方向，不是交付时间承诺。优先级会根据社区反馈、可复现问题与真实试点结果调整。

| 方向 | 当前已有 | 下一步讨论 |
| --- | --- | --- |
| 员工任务入口 | 独立 Web、Markdown 回答、检索引用、会话切换；保留 Electron | 流式输出、服务端会话持久化、任务执行轨迹、移动端体验 |
| 知识库 | 多格式导入、异步解析与分片、可见范围过滤、归档恢复 | 文档版本与有效期、OCR、引用定位、检索质量评测、重复/冲突检查 |
| 语义检索 | 可选兼容 Embedding；应用层混合排序 | 独立向量索引、Qdrant/Atlas 等可选后端、增量索引、重排模型与基准数据集 |
| Skill 工厂 | manifest 校验、审核发布、启停、Runtime 与输出校验 | 多步编排、版本回滚、测试沙箱、员工提交入口、可视化配置 |
| 业务系统接入 | HTTP 能力路由、字段映射、认证、失败审计；演示 Adapter | 高级映射表单、OAuth2 刷新、业务身份映射、可复用 Adapter 模板、MCP 接入 |
| 身份和治理 | JWT/OIDC、知识可见范围、Skill 角色门控、原子一次性确认 | scope 的运行时强制授权、业务行级权限、管理员分权、确认 UX、限流与访问策略 |
| 写入可靠性 | 确认绑定用户/参数/配置、不自动重试 | 幂等键、业务状态回查、补偿流程、失败任务处理和长期运行任务 |
| 生产部署 | 本地启动步骤、配置样例、测试和公开检查 | 可验证的容器化一键启动、外部对象存储、备份恢复、监控与多实例验证 |
| 社区与生态 | MIT、贡献指南、Issue/PR 模板、公众号介绍 | 场景库、脱敏试点报告、文档翻译、企业集成教程 |

## 特别欢迎这些反馈

- 你最想让 AI 帮忙的企业任务是什么？
- 哪个系统最难接入：没有 API、身份不统一，还是权限不清晰？
- 知识问答在哪些问题上答不准？能否提供可公开的测试资料？
- 什么操作必须“人点确认”，什么操作可以自动执行？
- Web 与桌面端如何分工最适合你的组织？

请在 [GitHub Discussions](https://github.com/chencheng666/openworkmate/discussions) 分享思路，或者直接提交 [Issue](https://github.com/chencheng666/openworkmate/issues)。PR 可以从一份接口样例、一段测试或一个文案改进开始。
