# 本地工作台：Web、检索与桌面边界

## 今天可以验证的功能

1. 打开管理后台的「企业外观」，修改名称，上传最长边 512 像素、最大 64 KB 的 PNG，选择配色。先看预览，再保存。平台管理员可写，员工可读自己的品牌。注销后不保留品牌缓存。
2. 开启真实模型时，先用公开示例资料。知识库重新建立索引后，在员工端问「请把报修升级规则整理成表格」，核对引用、表格和下载的 Markdown、CSV。
3. 试问「把以下示例工单数列成两列表格：待办 12，已处理 8，已关闭 6」。对这类有 2–12 行、数值非负的表格，点击「生成柱状图」可查看并下载 SVG。这里只做数据绘图，不调用图像生成模型。
4. 对回答中的 Markdown 图片、图片文件链接和 MP4/WebM/OGV 链接，员工可按需预览。源文件必须存在且当前浏览器有权读取、支持解码。任意 HTML 不会执行，Office 原生文件并没有在线编辑器。

## 小规模检索怎么部署

启动一个 Node 服务和 MongoDB 即可，默认只监听回环地址。MongoDB 存资料、切片、模型标识和向量，后端先筛本租户可读文档，再用 Bigram 和余弦相似度排序。向量由远程模型生成，本机不需要 GPU；没有配置向量模型时使用关键词。它不是 HNSW/ANN 索引，符合权限的切片增加时，查询仍会线性变慢。先测真实文档量、并发下的 P95、峰值内存和问答命中，再考虑接独立向量索引。新增索引也必须保留租户与权限过滤。

每家公司可独立部署，也可通过受信的身份系统提供不同 tenantId。开发身份只用于本地。不要把开发端口、MongoDB 或带有模型 Key 的演示环境直接暴露上网。

## 何时值得安装 Tauri

浏览器足以承担对话、引用、图表、媒体播放和下载。桌面端最有价值的是减少员工在**其他软件与助手之间**的操作：

| 工作场景 | 建议给桌面端的能力 |
| --- | --- |
| 在工单系统工作时要查一条制度 | 全局快捷键唤起小窗；由用户粘贴或明确授权读取选区，不后台采集剪贴板 |
| 每周把报表存入同一目录 | 首次选择并授权目录，以原生对话框保存，原位显示文件；不开放任意路径读写 |
| 等待视频或长报表 | 托盘显示任务、完成时通知；真正的任务队列与状态在服务端，退出客户端不影响执行 |

**本地第一版**：项目的 `desktop/` 是 Tauri 2 客户端，嵌入员工端构建产物。先按首页启动 MongoDB 和后端，在 Mac 安装原生 stable Rust 与 Xcode Command Line Tools，再于仓库根目录运行 `pnpm desktop`。产物在 `outputs/desktop/OpenWorkMate.app`，仅做本地临时签名，不是公证发行包。关闭红色窗口按钮后仍可用 ⌘⇧空格唤起；⌘Q 退出后需重新打开。应用仅保存系统目录选择器返回的路径，对同名文件加序号，不覆盖。

桌面访问固定的 `http://127.0.0.1:18790/api`；后端仅在回环监听时放行桌面来源。后端、MongoDB 和模型凭证不嵌入安装包。正式企业分发仍需处理 SSO 原生回调、签名、公证、更新和各平台真机验证。

参阅 [Tauri 的 Vite 配置](https://v2.tauri.app/start/frontend/vite/)、[原生权限边界](https://v2.tauri.app/security/capabilities/) 和 [全局快捷键](https://v2.tauri.app/plugin/global-shortcut/)。

## 统一文件结果

在员工端右上角打开「文件结果」，或点某条回答下的「生成文件…」带入正文。MD 保留原文；CSV 导出首张 Markdown 表，若没有表格则逐段分行；PNG 排版摘要；MP4 将摘要排成最多四张无声简报卡，每张 3 秒。它们均不需要调用付费媒体模型。Linux 部署建议安装中文字体（如 Noto Sans CJK SC）；视频需要与平台匹配的 FFmpeg，服务端依赖提供相应预编译包。

`POST /api/results` 返回 202，状态依次为 queued → running → ready 或 failed。`GET /api/results` 返回当前用户最近 100 项；`GET /api/results/:id/file` 仅允许同一租户和用户读取就绪文件。输入最多 12,000 字符；单结果最大 8 MiB，结果与元数据存 MongoDB，7 天过期。首次版本单进程串行消费任务，重启后继续排队任务，中断的运行任务会被标记失败。以后的视频供应商、长任务预算与对象存储可继续复用这套接口。
